What's going on

Fumola's runtime, Adapton, records every force-of-a-thunk in a Demanded Computation Graph (DCG). When you ask for the first day alice and bob are both free, the thunk that decides it forces a per-day pair-thunk for monday — which itself reads alice's and bob's monday cells. If monday works, the search short-circuits. If not, tuesday gets forced. The DCG records exactly which pair-thunks were inspected.

Now ask for the first day alice + bob + carol are all free. The team thunk for each day is defined as pair_ab AND pair_ac, so it reuses the pair-AB thunks already in the cache. You'll see this directly in the log: the team query's row will show some green hits (one per day already forced by your earlier pair-AB query) alongside the red cold misses for the pair-AC thunks it has to compute fresh.

That's Adapton: the cache discipline isn't ad-hoc — it falls out of the dependency structure of named cells and thunks. Different consumers of the same intermediate computations share work automatically. In a real deployment of this calendar inside a TEE, every query produces both a verdict and a structured DCG receipt the TEE can sign over; verifiers replay locally (using the same wasm you're running now) and confirm by hash equality.
